# 从 PoC 核查结果移植的工程加固

日期：2026-10-28。核查对象：`lingyicute/StarryPass` 的 `main@8d5dd9306fa70db278a636547667dbf86bd8c066`。参考修复：PoC 分支 `1d2169d`。

**结论：使用成熟密码学原语并未消除共同的 UI / Service Worker 缺陷。生产核心另有异步清理和缓存 nonce 故障需要单独处理，不能直接复制同步 PoC 核心。** 本次保持原派生规范、生产依赖和正常合法输入的结果；原有黄金集与依赖锁文件不改。

## 1. 逐项判定

“实测”包括明确注明的故障注入，不表示浏览器或随机源在正常使用中已发生此类故障。“未清理”指持有相关视图时仍可看到字节，不等于已证明可远程读取或系统不会回收内存。

| PoC 相关问题 | 生产版原状与证据性质 | 本次处理 |
|---|---|---|
| 输入变化后仍可复制旧结果 | 实测：编辑代号后、防抖前复制仍启用 | 输入/策略变化立即作废编号、输出、评分与复制状态 |
| 清空后旧回包重新出现 | 实测：reset 后回复旧 id，会显示 `LATE_PASSWORD` 且可复制 | 任务 id、原输入/策略、Worker 实例与当前任务共同校验；重置终止 Worker |
| 输入堆积重 KDF | UI 可向同一 Worker 连续发送；生产核心虽串行化，旧计算仍排队 | UI 单活动任务、只保留最新待办；过期/重复回包不释放其他任务 |
| Worker 加载或通信失败 | 原 UI 无完整的 error/messageerror/发送异常恢复 | 构造、发送、加载、消息错误均回退本地异步生产核心 |
| Worker 卡住 | 实测：超过 60 秒仍未终止 | 超时 terminate，必要时创建新 Worker，仅重派最新待办 |
| 生产版异步本地完成竞态 | Web Crypto 返回 Promise，不能照搬 PoC 的 deriveSync | 完成回调核对具体 payload；旧完成/拒绝不得释放 reset/BFCache 后的新任务 |
| PIN 与长度芯片错乱 | 默认 PIN 本来就是 6 位；实测点击长度芯片可变成 8 位，再返回 full 会丢失原选择 | 默认 6 位不变；PIN 禁用不适用芯片，单独计算有效长度，不覆盖 full/alnum 长度 |
| PIN / 短输出评分过高 | 实测错误路径 8 位 PIN 显示“极强 · 长期防破解” | 用产生当前结果的 payload、实际长度和字符池空间上界约束；不换模型、位置或文案 |
| 随机源抛错后留下 nonce | 故障注入：第一次 getRandomValues 抛错；第二次却沿用失败的 nonce 并成功派生 | 只在随机填充成功后发布 nonce，失败清零并持续 fail-closed；仍不允许弱随机回退 |
| 缓存 nonce 作用域 | nonce 原在模块全局，某实例 wipe 会影响其他实例的缓存命中 | nonce 与缓存一起移入工厂实例 |
| 异步清空不是可等待屏障 | 原核心已有串行队列，但 wipeSession 不返回 Promise、旧请求照常计算和返回 | 返回排队清理 Promise；generation 立即作废旧活动/排队任务；旧结果不得进入缓存 |
| 异常路径不清理 | 注入 HMAC / KDF 等错误后，编码输入与消息视图仍非零 | 输入、盐、长度前缀副本、HMAC 消息、候选会话密钥及合成流以 finally 清理 |
| HKDF 临时输出与旧块 | 正常路径实测：原生 deriveBits 的完整返回及被替换的 32 字节切片未显式清理 | 原生完整输出复制所需块后清零；替换/销毁流时清旧块，释放密钥句柄引用 |
| 表查找命中原型属性 | 实测 mode=constructor 被视为有效项；tier 有同类代码 | 改为 own-property 查找；保留生产黄金集的普通未知值回退，不移植 PoC 的严格拒绝策略 |
| WASM 降级无诊断 | 启动交叉门控本来就有，但异常/不一致静默回退 | 一次性、不含输入/异常文本的降级提示；启动失败重置 provider 状态 |
| 剪贴板反馈/焦点 | 原异步复制可给新结果显示旧“已复制”；textarea 后备复制不恢复焦点 | 固定复制时的文本/id，过期反馈不改新结果；移除临时 textarea 并恢复焦点 |
| 口令自动 live 播报 | 原结果区 aria-live=polite | 改 off；不宣称能阻止读屏用户手动读取 |
| 运行时外链字体 / 缺少 CSP | 原字体失败时存在两条外网回退，缺少本页 CSP/referrer 限制（静态确认） | 保留原内嵌字体字节，移除运行时外链；CSP 保留真正 WASM 能力，使用 no-referrer |
| PWA 清单缺失 | 已有 SW / 移动元数据，但无 manifest | 添加同作用域清单，复用现有图标 |
| SW 旧核心缓存不更新 | cache-first；仅更新 HTML/core 且不更新 SW 时会继续使用已缓存资源 | HTML 和脚本重新验证；离线优先最近运行时副本，入口/query 共享最新 shell |
| SW 缓存生命周期/隔离 | cache.put 未由 waitUntil 等待；激活删除其他应用缓存；GET 范围宽且不限缓存条目 | 同步登记真实写入 Promise、路径命名空间、严格 origin/path 比较、仅缓存资源清单 |
| CI / Pages / 字体身份注入 | 发布不等待测试；Actions 浮动标签；事件身份直接插入 shell（静态确认） | 固定既有官方 Actions 的完整 SHA，身份经环境变量传入；Pages 等待同提交全部回归 |

## 1.1 推送前第二次复核补充

以下问题在第一轮移植后再次审查时，通过可控对象复用或故障注入复现；不是声称正常生产提供方已发生这些故障。补充修复已归入对应的核心/UI/PWA 提交，并加入回归：

| 复查发现 | 实测与修复 |
|---|---|
| 异步队列保留调用者可变请求 | 连续复用同一对象，修改 counter 后两条旧请求均使用新值。现在调用时快照六个派生字段；取字段异常仍以 Promise、FIFO 和统一清理路径处理，保留 wipe 作废规则 |
| 畸形 Argon2 输出继续进入 HKDF | 启动 KAT 通过后注入空/31/33 字节输出或数字 32，原包装仍能给出“口令”。现在先检查二进制类型，再要求严格 32 字节；错误字节视图清理、缓存作废。启动门控也使用相同类型检查；合法的 32 字节全零值不被武断拒绝 |
| UI 畸形成功结果 | 本地 `null` 返回导致未捕获异常且 busy 不结束；长度或字符池错误的字符串可被复制。现在本地以 finally 释放对应任务，Worker 仅接受 `ok === true`；两条路径共同核对请求长度和原字符池，并测试后续恢复 |
| 运行时缓存失败挡住完好预缓存 | 注入 runtime open 失败，即使安装缓存存在也无法离线读取。现在用明确 cacheName 的 CacheStorage.match 独立尽力读取，不为离线查询新建缓存；双侧存储失败时保留原 HTTP 503/网络错误，不跨入其他应用缓存 |

另以真实源码/发行包、WASM/noble 四路验证请求复用与双引擎并发，且在真实 Chromium Service Worker 中只注入运行时缓存失败，确认预缓存仍能加载核心并离线派生。字体工作流的身份环境变量/引号也重新用含 shell 片段及 `--global` 的测试值核对，未复现额外注入问题，因此未再改该工作流。

## 2. 已解决或不适用，不机械照搬

- **底层原语**：生产版不是 PoC 手写 Argon2/WASM 核；不移植其内存 arena 与参数验证代码。生产公开 API 的 KDF 成本固定，库有自己的校验，本次不修改第三方原语或 vendored 二进制。
- **随机源弱回退**：生产版原本已无 Math.random 回退。问题是失败 nonce 先被发布，而不是正常情况下仍在使用弱随机源。本次保持生产版 CSPRNG 必需策略，不照搬 PoC 的“无随机源则关闭缓存继续”路径。
- **自检和 provider 测试**：生产版原来已有两提供方 RFC KAT 与发行包 provider 断言；不能说原先完全没有真 WASM 验证。本次补四路固定答案、真实浏览器提供方检查，并让离线 parity 缺少提供方时失败而非 SKIP。
- **主题**：原生产版在深色系统下保存浅色后仍正常恢复；未将其列为待修缺陷。
- **主密码长度**：原版没有 512 maxlength，继续不加上限。长于 512 UTF-16 单位的兼容向量与浏览器测试用于防回归。
- **输入提示**：保留 master 的 autocomplete=off 与原 PIN 提示；不声称浏览器/密码管理器必定服从提示。
- **图标路径**：原 favicon 已是相对路径，不重复声称修复。
- **自动清除剪贴板**：原生产版无该功能；不引入读取/定时清除，不能可靠承诺系统剪贴板历史被擦除。

## 3. 不变的协议与兼容边界

以下均保留：

- UTF-8(NFC(master))；UTF-8(NFC(trim(code)))，代号区分大小写，不新增 lowercase/NFKC；
- 原域分离字节、长度前缀、tier id、Argon2id m/t/p 与 associated data；
- 原 Web Crypto / vendored hash-wasm / @noble/hashes 依赖，未改 package-lock、原 44 条 golden 或 7 条 vectors；
- HKDF 流字节顺序、counter/length 的原有 parseInt/夹取规则、字符池、最多 128 次候选重试和既有兜底；
- 普通未知 mode/tier 的 full/standard 回退（原黄金集明确约定）；原型属性不能冒充合法项；
- 默认 full 16 / PIN 6、UI 布局、强度模型和指示器的位置/文案。

**不继续复刻旧 UI 错误状态。** 老版本曾可能因 PIN/长度状态错乱生成 6 位 full 或 8 位 PIN；底层 API 的合法 6/8 位参数仍可复现当时输出。若既有账户使用这些路径的结果，应按当时实际模式/长度复现，而不是假定界面原选择与实际输出相同。

## 5. 本轮没有改变的设计风险与限制

- 固定站点盐仍允许针对相同 code/tier 跨用户复用候选主密码的预计算；是否安全仍取决于主密码选择。加用户盐/额外秘密不是本轮兼容补丁。
- 换 tier 会换密码：不仅盐中含 tier，Argon2 的成本参数本身也决定输出。仅删除盐中的 tier 不能保持换档结果。
- 原启发式评分并不是实际攻击猜测排名。输出空间上界不是实际熵或破解时间；不提供未经验证的“高估若干倍”结论。
- 没有证明最终合成分布严格均匀，也不能无条件把某个公开短语当作随机 Diceware 样本。
- 不替换 zxcvbn：更换评分模型本身不必改派生密码，但属于另需确认的模型/设计变更。
- 清零是尽力清理受控字节缓冲：不保证 JS 字符串、DOM、浏览器/GC/第三方库/系统副本被物理擦除。容量保留不等于数据必然残留；不照搬 PoC 已撤回的“正常路径尾部泄漏”推断。
- 保留原本本地 WASM 优先策略，它可能在调用期间阻塞主线程；noble 异步路径的周期让步不等于 WASM 也可中断。本地回退不能强制打断进行中的原生调用；清空会作废其结果并在安全边界清理，不能保证 pagehide 后立即归还内存。Worker 可终止，但同样不保证系统安全擦除。
- 未证明多标签并发部署原子性，未穷举内存耗尽；未在真实手机、Safari/Firefox 或各类扩展/系统剪贴板历史上验证。CSP 不抵御同源恶意代码或有足够权限的扩展。
- 保留“生产版本”的项目定位不等于本轮提供生产安全认证。库成熟、启动自检、兼容性测试与应用安全审计是不同层次的保证。
